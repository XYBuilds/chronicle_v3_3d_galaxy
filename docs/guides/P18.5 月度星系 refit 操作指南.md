# P18.5 月度星系 refit 操作指南

本指南说明 **Phase 18.5**（月度全量门槛重算 + UMAP refit + Procrustes 对齐 + Supabase 回写 + 静态导出）及 **P18.5b**（锚点**软闸**、结构化日志、`monthly_refit_meta.json` artifact）落地后，你在 **本仓库内接下来要完成的事项**：一次性准备、本地与 CI 配置、验收顺序与排错。实现细节以脚本与 workflow 为准；总体规划见 `.cursor/plans/phase_18_data_infrastructure_9ccb7a3f.plan.md` 中 **P18.5 / P18.5b** 小节。

**建议先完成再读本节**：

- [Supabase 操作教程](./Supabase%20操作教程.md)（P18.2 表结构、`service_role`、勿提交密钥）
- [P18.4 每日投票刷新与导出入口指南](./P18.4%20每日投票刷新与导出入口指南.md)（冻结门槛 `threshold_versions`、nightly、`movies_pending` 的含义）

**与 P18.4 的分工（必读）**：

| 维度 | P18.4（每日） | P18.5（月度） |
|------|----------------|----------------|
| **动态门槛** | **不**重算；只读当前 `is_active` 的冻结 `thresholds_json` | **重算** `compute_year_to_vote_threshold`，**写入新行** `threshold_versions` 并设为 active |
| **坐标 x/y** | **不变** | 全量 `fit_transform`（CPU DensMAP）后 **`align_to_reference`**，回写 `movies` |
| **`movies_pending`** | 新过线片 **INSERT** | 合并进 `movies` 后 **DELETE** 对应 pending |
| **导出 `meta.version`** | `YYYY.MM.DD.daily.<seq>` | `YYYY.MM.DD.monthly.<seq>`，且可带 `meta.threshold_version` |

## 1. 你在 P18.5 内要完成的「待办清单」（按顺序）

按下面顺序做完，月度 refit 路径即处于**可运营**状态（部署到 Cloudflare 仍属 **P18.6**）。

1. **确认数据库与只读基准**
   - `galaxy_v1_reference` 已导入且 **不再被脚本更新**（P18.3 约定）；`movies` 与 v1 导入时一致或已由 nightly 维护。
2. **准备 embedding 四件套（最关键）**
   - 在本机（或可信构建机）跑完整管线，生成与 **行对齐** 的四个文件（见第 2 节）。缺一则 `monthly_refit.py` **启动即退出**。
3. **让 GitHub Actions 能拿到四件套（若要用 CI 跑月度）**
   - 推荐：在 Secrets 中设置 **`GALAXY_EMBED_BUNDLE_URL`**（zip 直链，见第 2.3 节方案 D）。
   - 亦可：当前 workflow **会 `restore` Actions Cache**（不在月度 job 末尾 **`save`**）；若未用 URL 且仓库里**没有**这四个文件，首次需在 CI 可见路径放入它们（见第 2.3 节 A/B）。
4. **配置 Secrets**
   - 与 nightly 相同：`SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY`、`KAGGLE_USERNAME`、`KAGGLE_KEY`。
   - 若用 **第 2.3 节方案 D（URL zip）** 提供四件套：另设 **`GALAXY_EMBED_BUNDLE_URL`**（见该节 zip 契约）。
5. **本地冒烟**
   - `--dry-run`：验证 Kaggle/raw、清洗、门槛与 membership 数量（不写库、不跑 UMAP）；日志中会打印 **`raw_sha256prefix`** 与 **`bundle_fingerprint`**（便于与 CI 对齐）。
   - 再酌情做一次 **`workflow_dispatch`** 或本机完整跑通（写库 + 导出 + `validate_galaxy_json`）。
6. **对照 P18.1 基准（强烈建议）**
   - 阅读 `docs/reports/` 中与 **Phase 18.1 / GHA core benchmark** 相关的报告：确认 **`timeout-minutes: 180`** 与 runner 资源是否够用；若月度频繁 OOM 或超时，按规划降级为**季度本机 refit + 上传**（见第 8 节）。
7. **P18.6（Cloudflare Pages）**
   - Workflow 已内建 **构建 `frontend/dist` + `pages-action` 上传**；在 GitHub 配置 **`CLOUDFLARE_*`** Secrets 并完成 Cloudflare 侧项目与域名即可（见 [P18.6 Cloudflare Pages 切换操作指南](./P18.6%20Cloudflare%20Pages%20切换操作指南.md)）。

## 2. 核心依赖：`data/output` 下四个文件（embedding bundle）

脚本：`scripts/cron/monthly_refit.py`  
默认目录：`data/output/`（可用 `--cache-dir` 修改）。

| 文件 | 作用 |
|------|------|
| `cleaned.csv` | 与下列三个 `.npy` **按行一一对应**；每行 `id` 用于把缓存向量映射到「当月清洗后仍过线的影片」。 |
| `text_embeddings.npy` | 形状 `(N, 384)`，MiniLM，与管线一致。 |
| `genre_vectors.npy` | 与 `genre_encoding` 输出维度一致。 |
| `language_vectors.npy` | 与当时语言 one-hot 维度一致。 |

**契约**：`N = len(cleaned.csv)`，且三个 `.npy` 的第 `i` 行对应 `cleaned.csv` 第 `i` 行的 `id`。月度任务会从 **当月** `run_cleaning_pipeline(raw)` 得到的 **`cleaned`** 中取成员 id；对仍在宇宙内的旧片，用 **`id → 缓存行索引`** 取向量；对 **`movies_pending`** 中的新片，用表里 **BYTEA**；若仍有极少数 id 既不在缓存也不在 pending，脚本会 **当场 MiniLM 编码**（应极少出现，前提是 nightly 正常）。

### 2.1 在本机生成四件套（推荐路径）

在仓库根目录、已安装 `requirements.cpu.txt` 的前提下，按你们既有 **Phase 2 管线**从 raw → cleaning → embedding → genre/lang → 写出 `data/output/cleaned.csv` 与三个 `.npy`（具体入口可能是 `scripts/run_pipeline.py` 或文档中的分步命令；**不要**在对话里打开超大 `data/raw/TMDB_all_movies.csv`）。

生成后建议自检：

```powershell
python -c "import numpy as np, pandas as pd; df=pd.read_csv('data/output/cleaned.csv'); t=np.load('data/output/text_embeddings.npy'); print(df.shape, t.shape)"
# 期望：第一维相等；text 第二维为 384
```

### 2.2 与 Supabase 里影片集合的关系

- 缓存里的 `N` 通常对应 **某次全量导入时的宇宙规模**（例如约 59k）。  
- **月度**当月 `cleaned` 的成员集可能与 `N` 略有出入（新增 / 门槛变化）。脚本对 **缓存缺失的 id** 会尝试 pending 向量或在线编码；**长期大量缺失**说明缓存过旧，应 **重新跑管线刷新四件套**。

### 2.3 CI 上如何让我们「看得见」这四个文件

`.github/workflows/monthly_refit.yml` 中：

- 使用 **`actions/cache@v4`** 按路径恢复上述四文件；
- 紧接着有 **Verify** 步骤：任一缺失则 **整个 job 失败**。

因此 **首次**启用月度 CI 时，你必须任选其一（或组合）：

| 方案 | 说明 |
|------|------|
| **A. 将四文件提交到 git** | 简单但不友好：体积大（数百 MB 级），通常需 **Git LFS** 或独立仓库；公共仓库注意带宽与克隆体验。 |
| **B. 用别的 workflow 预先写入同一版本的 Cache** | 需单独设计「只跑一次」的 seed workflow（在 job 内把四文件放到 `data/output/` 并成功结束，且 **cache action 的 key 与 monthly 一致或可命中 `restore-keys`**）。当前仓库**未**内置该 seed workflow，需你自行加或手动灌 Cache。 |
| **C. 月度仅在本地/私有跑 refit** | 本机有数据与算力时运行 `monthly_refit.py`；CI 仅保留 `workflow_dispatch` 作实验或关闭 schedule。 |
| **D. URL 下载 zip（推荐长期自动跑）** | 在 **Settings → Actions secrets** 中设置 **`GALAXY_EMBED_BUNDLE_URL`**：指向 **zip** 的直链（Release 资产、R2/S3 预签名 URL 等，需 `curl` 可无交互下载）。workflow 在 Restore cache **之后**、Verify **之前**解压；若配置了该 secret，**会覆盖**当次 runner 上来自 cache/仓库的四文件。见下「zip 契约」。 |

**zip 契约（方案 D）**：zip 内任意目录深度中须能找到 **`cleaned.csv`**，且与其 **同一目录** 下并列存在 `text_embeddings.npy`、`genre_vectors.npy`、`language_vectors.npy`（与第 2 节四件套一致）。

**Secret 填写**：`GALAXY_EMBED_BUNDLE_URL` 的值必须是 **一行**、以 `https://` 或 `http://` 开头的直链（不要加引号、不要首尾空格；从记事本粘贴时易带入换行，会导致 `curl: (3) Malformed input`——workflow 已做去换行/trim，但仍建议你在 GitHub 上打开 secret 预览确认只有 URL）。

**现状小结**：若默认分支上 **没有** 四文件、**Cache 从未命中**、且 **未设置 `GALAXY_EMBED_BUNDLE_URL`**，GitHub 上的 **schedule 月度任务会一直失败**，直到你完成 A/B/D 之一。

## 3. 脚本做了什么（便于排错时对照日志）

以下顺序与 `scripts/cron/monthly_refit.py` 一致。

1. **检查四文件**是否存在；否则打印 CACHE MISS 并退出。
2. **Raw 数据**：默认 Kaggle 下载（与 P18.4 同一数据集）；或 `--input-csv` 指定本地 raw。
3. **门槛与 membership（动态）**
   - `run_cleaning_pipeline_before_vote_threshold` → `compute_year_to_vote_threshold` → 得到唯一 `thr_map`。
   - 用**同一对象**调用 `apply_frozen_vote_threshold` 得到 final membership；该集合是当月 UMAP、维度阻断、写入 `threshold_versions.thresholds_json` 的唯一数据边界。
   - 对门槛前语料只记录 unknown language/genre 观测；只有 final membership 的 `assert_no_dim_drift` 可阻断。通过后才将库内 **所有** `threshold_versions.is_active` 置 `false`，再 **`upsert`** 新版本（`version` 为主键），`is_active = true`（默认 `p18_monthly_YYYYMMDD_<GITHUB_RUN_NUMBER>`，可用 `--version-label` 覆盖）。
4. **读缓存与 pending**：加载四件套；分页读取 **`movies`**、**`movies_pending`**、**`galaxy_v1_reference`**。
5. **拼特征矩阵**（行顺序 = `cleaned` 成员 id **排序**）：缓存 / BYTEA / 在线编码。
6. **UMAP**：`fuse_modalities` → `_fit_umap_learn`（`densmap=True`，`n_neighbors=300`，`min_dist=0.4`，`metric=cosine`，`random_state=42`）。
7. **Procrustes**：`align_to_reference`（锚点为 **`galaxy_v1_reference`** 中存在的 id）。
8. **质量闸（P18.5b：软闸 + 可观测）**
   - 对齐后在锚点集上计算与 reference 的 **L2**，得到 **`anchor_mean_l2`**、**`anchor_max_l2`**、**`n_anchors`**。
   - **模式**由 **`MONTHLY_ANCHOR_MODE`** 或 **`--anchor-mode`** 控制（CLI 优先于环境变量；`--skip-anchor-rmse-abort` 等价 **`skip`**）：
     - **`soft`（CI 默认）**：均值高于 **`--anchor-rmse-abort`**（默认 `0.25`）时 **仅 WARN 并继续**；仅当均值高于 **`MONTHLY_ANCHOR_SOFT_FAIL_MAX`** / **`--anchor-soft-fail-max`**（默认 **50**）或非有限数时 **退出码 1**（极端残差 / 结构性异常）。便于 Kaggle raw 与四件套不完全同快照时仍跑通链路，用数周日志与 artifact 再定硬闸。
     - **`hard`**：均值高于 **`--anchor-rmse-abort`** 即 **退出码 1**（与早期行为一致）；适合本地或已确认四件套与 reference 严格对齐时。
     - **`skip`**：不因锚点残差失败（排障 / 人工放行）；**生产慎用**。
   - **一行可 grep 日志**：以前缀 **`monthly_refit_kv`** 打印键值（如 `anchor_mean_l2=`、`n_fit=`、`threshold_version=`、`raw_source=`、`bundle_fingerprint=` 等），便于在 Actions 日志里检索。
   - **运维元数据文件**：成功或锚点/export/validate 失败时，在**仓库根目录**写入 **`monthly_refit_meta.json`**（与 `galaxy_data` **分离**，不污染前端契约）；GitHub workflow 将其与导出物一并 **upload-artifact**。
9. **写库**：对当月成员 **upsert `movies`**（合并票数与 x/y/z、`last_xy_refit`）；从 **`movies_pending`** **删除**已合并 id。
10. **导出**：子进程调用 `scripts/cron/export_from_supabase.py`，传入 `--version-branch monthly`、`--threshold-version <本次版本号>`，再运行 `scripts/validate_galaxy_json.py`。

**刻意不做的**（与规划一致）：**不**删除「仍在 `movies` 里但当月已低于动态门槛」的影片（仅日志里统计 `below_threshold`）；是否物理删除留给产品与后续策略。

## 4. 本地环境变量与常用命令

与 P18.4 相同，需要：

- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`

可选：根目录 `.env`（已被 `.gitignore`，勿提交）。

**锚点闸（与 CI 对齐时建议显式设置）**：

| 变量 / 参数 | 说明 |
|-------------|------|
| `MONTHLY_ANCHOR_MODE` | `soft` \| `hard` \| `skip`；未设置且未传 CLI 时，脚本默认 **`hard`**（本地与旧行为一致）。 |
| `MONTHLY_ANCHOR_SOFT_FAIL_MAX` | 仅在 **`soft`** 下生效：均值锚点 L2 超过该值则失败（默认 **50**）。 |
| `--anchor-mode` | 覆盖环境变量。 |
| `--anchor-soft-fail-max` | 覆盖 `MONTHLY_ANCHOR_SOFT_FAIL_MAX`。 |
| `--anchor-rmse-abort` | **`hard`**：超过即失败；**`soft`**：超过则 WARN，真正失败阈值为 soft 上限。 |
| `--skip-anchor-rmse-abort` | 已弃用文案，行为同 **`skip`**。 |

### 4.1 只验证清洗、final membership 与门槛（不写库、不跑 UMAP）

先确认数据库只读边界可用，再使用与生产同型的本地快照和完整四件套：

```powershell
python scripts/cron/check_supabase_health.py
python scripts/cron/monthly_refit.py --input-csv data/subsample/TMDB_all_movies_random20.csv --cache-dir data/output --dry-run
```

`--dry-run` 会检查四文件、读取 raw、生成一份 `thresholds_json`、打印 pre-threshold 与 final-membership 的 shape/未知语言计数/年份范围，并在写库前退出（**不**连接 Supabase、**不**跑 UMAP、**不**执行导出）。不要用 `DIM_DRIFT_FORCE_SKIP` 获得绿色结果；final membership 出现未知维度时应保持失败，先完成 palette/bundle 迁移。

### 4.2 完整月度（写库 + 导出 + 校验）

```powershell
python scripts/cron/monthly_refit.py
```

可选参数（见 `python scripts/cron/monthly_refit.py -h`）：

| 参数 | 含义 |
|------|------|
| `--input-csv PATH` | 跳过 Kaggle，使用本地 raw |
| `--cache-dir PATH` | 四件套目录（默认 `data/output`） |
| `--version-label STR` | 写入 `threshold_versions.version` 的主键字符串 |
| `--anchor-mode` | `soft` / `hard` / `skip`：锚点闸模式（见 §4 环境变量表；本地不传 env 时默认 `hard`） |
| `--anchor-rmse-abort FLOAT` | 见上表；与 `--anchor-mode` 组合使用 |
| `--anchor-soft-fail-max FLOAT` | 仅 `soft`：均值超过则失败（默认 50） |
| `--skip-anchor-rmse-abort` | 同 `skip` |
| `--skip-export` | 只 refit + 写库，不跑导出子进程 |

完整跑通后，仓库根目录会出现 **`monthly_refit_meta.json`**（已被 `.gitignore`，勿提交）；内容含锚点指标、门槛版本、指纹等，与日志中 **`monthly_refit_kv`** 行一致，便于留存对比。

### 4.3 单独再次导出（不写库）

若 Supabase 已更新，只需刷新静态 JSON：

```powershell
python scripts/cron/export_from_supabase.py --version-branch monthly --threshold-version p18_monthly_20260505_123 --export-seq manual1
```

（`threshold-version` 应与当月写入库的版本号一致，便于 `meta` 可追溯。）

## 5. GitHub Actions：`.github/workflows/monthly_refit.yml`

| 配置项 | 说明 |
|--------|------|
| **触发** | Cron：`0 20 1 * *`（**每月 1 日 UTC 20:00**）；以及 **`workflow_dispatch`**。 |
| **手动参数** | **`anchor_mode`**（`soft` / `hard` / `skip`，默认 **`soft`**）：写入当次 job 的 **`MONTHLY_ANCHOR_MODE`**。**Schedule** 触发时没有 manual input，表达式回退为 **`soft`**，与 P18.5b「先观测再收紧」一致。 |
| **Secrets** | 必填：`SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY`、`KAGGLE_USERNAME`、`KAGGLE_KEY`。可选（四件套来源）：**`GALAXY_EMBED_BUNDLE_URL`**（zip 直链，见第 2.3 节方案 D）。 |
| **资源** | `ubuntu-24.04`，`timeout-minutes: 180`；`OMP_NUM_THREADS=4` 等与 benchmark / nightly 一致，减轻 BLAS 过度订阅。 |
| **Env** | `GALAXY_EXPORT_SEQ`、`GALAXY_EXPORT_VERSION_BRANCH=monthly`（导出侧也可用 CLI 显式传 `--version-branch monthly`）。另：**`MONTHLY_ANCHOR_MODE`**（见上）、**`MONTHLY_ANCHOR_SOFT_FAIL_MAX=50`**。 |
| **产物** | Artifact：`monthly_refit_meta.json`、`galaxy_data.json`、`.gz`、`galaxy_search_index.json.gz`。 |
| **部署** | Cloudflare 步骤已注释，待 **P18.6** 与 nightly 同步启用。 |

**推荐首次验收**：

1. 确认第 2 节四文件在 CI 可见：**已设 `GALAXY_EMBED_BUNDLE_URL`**，或 **Cache 已命中**，或 **仓库内 `data/output/` 四文件**。  
2. **Actions → P18.5 Monthly galaxy refit → Run workflow**；需要严格对齐 v1 时可把 **`anchor_mode` 选为 `hard`**，排障可临时选 **`skip`**（慎用）。  
3. 看日志：搜索 **`monthly_refit_kv`** 与 **`resolved anchor_mode=`**；核对门槛年份数、membership、UMAP 耗时、**`anchor_mean_l2` / `anchor_max_l2` / `n_anchors`**、`below_threshold`、upsert 批次、`threshold_versions` 版本号。  
4. 下载 artifact：对照 **`monthly_refit_meta.json`** 与上述 KV 行；抽查 `galaxy_data` 的 `meta.version`、`meta.threshold_version`（若导出脚本写入）。  
5. Supabase：抽查 `movies` 中若干行的 `last_xy_refit`、`x/y`；`movies_pending` 是否减少；`threshold_versions` 仅一行 `is_active=true`。

## 6. 导出物 `meta` 约定（P18.5）

`scripts/cron/export_from_supabase.py` 支持：

- **`--version-branch daily|monthly`**（也可用环境变量 `GALAXY_EXPORT_VERSION_BRANCH` 覆盖为 `daily` / `monthly`）。  
- **`--threshold-version`**（或 env `GALAXY_THRESHOLD_VERSION`）：写入 **`meta.threshold_version`**（月度建议始终带上，便于区分「仅刷票」与「换门槛+换坐标」）。

版本字符串形如：`YYYY.MM.DD.monthly.<seq>`（`<seq>` 默认来自 `GALAXY_EXPORT_SEQ` / `--export-seq`，CI 常为 `github.run_number`）。

## 7. 常见问题与排错

| 现象 | 可能原因 | 处理方向 |
|------|-----------|----------|
| 启动即 **CACHE MISS** | `data/output` 缺四文件 | 第 2 节生成或放到 `--cache-dir`；CI 设置 **`GALAXY_EMBED_BUNDLE_URL`** 或参考第 2.3 节 A/B。 |
| **`need at least 3 movies for UMAP`** | 当月 `cleaned` 过少 | 检查 raw 是否截断、清洗是否过严；不要用极小 subsample 做生产验证。 |
| **Procrustes 报错 anchor < 2** | `galaxy_v1_reference` 为空或未导入 | 回到 P18.2 导入与 P18.3 锁定流程。 |
| **`ABORT anchor gate`（`hard`）或 soft 下超上限** | 锚点均值 L2 超过当前模式阈值 | **`hard`**：与旧版一致，优先核对四件套与 Kaggle/raw 是否同源、reference 是否匹配。 **`soft`**：仅当超过 **`MONTHLY_ANCHOR_SOFT_FAIL_MAX`**（默认 50）才失败；中间区间应出现 **WARN** + 仍写库（见 `monthly_refit_meta.json`）。临时排障可用 **`skip`** 或 workflow **`anchor_mode=skip`**（**生产慎用**）。 |
| **日志里 `WARN anchor soft-band`** | `soft` 下均值介于 `anchor_rmse_abort` 与 soft 上限之间 | 预期内观测行为；持续数周收集 **`monthly_refit_kv`** / artifact 再决定是否改 **`hard`** 或调 bundle。 |
| **仅有 `monthly_refit_meta.json`、导出失败** | `export_from_supabase` 或 `validate_galaxy_json` 非零退出 | meta 中 **`status`** 为 `aborted_export` / `aborted_validate`；先修导出或校验错误，再重跑。 |
| **月度超时 / OOM** | public runner 4C/16G 不足 | 参考 P18.1 GHA benchmark 报告；拉长 timeout、降负载，或改 **季度本机 refit**（规划允许）。 |
| **pending 合并不净** | upsert 失败中途退出 | 看 Supabase 日志与脚本栈；修复后重跑；必要时手动清理冲突 id。 |
| **`validate_galaxy_json` 失败** | 导出字段或 `meta` 不满足校验 | 对齐 `build_galaxy_payload` 与 Tech Spec；先本地单独跑 `export_from_supabase.py` 缩小范围。 |

## 10. 小结

P18.5 的实质是：**每月一次**用最新 raw 重算**动态门槛**并切换 **active** `threshold_versions`，对全体现役成员重算 **UMAP**，用 **v1 reference** 做 **Procrustes** 稳定视觉坐标，再回写 **Supabase** 并导出带 **`monthly` + `threshold_version`** 的静态数据。**P18.5b** 在同一脚本与 workflow 上补充：**默认软闸**（CI）、**稳定键名日志**、**`monthly_refit_meta.json` artifact**，便于在 raw/四件套不完全对齐时仍完成链路并积累残差分布，再决定是否恢复硬闸。你在 P18.5 阶段的核心事务是：**凑齐并长期维护 embedding 四件套**、**让 CI 能访问它们**、**跑通一次端到端验收**（含下载 meta 与对照 `monthly_refit_kv`），并根据 P18.1 结论决定是否把月度放在 GitHub Hosted 或改为本机季度重跑。

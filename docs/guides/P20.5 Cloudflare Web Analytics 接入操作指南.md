# P20.5 Cloudflare Web Analytics 接入操作指南

本指南面向运维：为 TMDB 电影宇宙前端（Cloudflare Pages 为主）启用 **Cloudflare Web Analytics**（cookie-free RUM beacon）。代码侧已在 **Phase 20 / P20.5** 接入：构建时若存在有效的 beacon token，会把官方脚本写入 `index.html`；未配置时站点行为与此前完全一致。

---

## 0. 你要达成的结果

完成后应满足：

1. 生产构建产物 `dist/index.html` 中包含 `static.cloudflareinsights.com/beacon.min.js`，且 `data-cf-beacon` 含正确的 `token`。
2. 真实用户访问线上站点后，在 **Cloudflare Dashboard → Analytics → Web Analytics** 中能看到 PV、来源国家、Core Web Vitals 等指标（通常会有延迟，部分面板需 **24 小时内** 才有有意义的数据）。
3. GitHub Actions 在执行前端 `npm run build -w frontend` 时能读到 token，无需把 token 写进仓库源码。

---

## 1. 原理简述（便于排错）

| 环节 | 说明 |
|------|------|
| **Beacon** | Cloudflare 提供的轻量脚本，向 `cloudflareinsights.com`（含 `cdn-cgi/rum` 等路径）上报匿名流量与性能数据；**不使用 cookie**，一般无需额外同意横幅（仍以你站点法务要求为准）。 |
| **构建期注入** | Vite 插件读取环境变量 **`VITE_CF_BEACON_TOKEN`**（非空则注入脚本）。实现位置：`frontend/vite.config.ts` 中的 `cfWebAnalyticsPlugin()`。 |
| **CI 映射** | GitHub Actions **Secret** 名为 **`CF_WEB_ANALYTICS_BEACON_TOKEN`**；在构建步骤里映射为 `VITE_CF_BEACON_TOKEN`，避免与仓库内其它 `VITE_*` 混淆命名。 |
| **未配置 secret** | Token 为空 → **不注入脚本**，构建仍成功；适用于尚未开通 Web Analytics 或故意关闭统计的环境。 |

## 2. Cloudflare 控制台：创建站点并获取 beacon token

1. 登录 [Cloudflare Dashboard](https://dash.cloudflare.com/)。
2. 进入 **Analytics → Web Analytics**（或账户左侧导航中的 **Web Analytics**，以当前控制台 UI 为准）。
3. **Add a site** / **创建站点**，填写你的 **前端对外 hostname**，例如：
   - Pages 默认域：`the-movie-cosmos.pages.dev`（请替换为你项目实际域名）
   - 若已绑定自定义域，可同时以生产域为准再建一条或按控制台说明合并（以 Cloudflare 当前产品界面为准）。
4. 创建完成后，控制台会给出一段嵌入代码，其中包含 **`data-cf-beacon='{"token":"……"}'`**。
5. **只复制其中的 `token` 字符串**（一长串字母数字类标识），保存到密码管理器或临时记事本；下一步写入 GitHub Secret。

说明：

- Token 会出现在公开页面的 HTML 里，**不属于强机密**，但仍建议通过 **Secret + 构建注入** 管理，避免误提交历史或fork 泄露路径混淆。
- 若 rotating token，在 Cloudflare 侧更新后，只需更新 GitHub Secret 并重新触发一次会构建前端的部署 workflow。

---

## 3. GitHub：配置 Actions Secret

路径：**仓库 → Settings → Secrets and variables → Actions → New repository secret**。

| Secret 名称 | 值 |
|-------------|-----|
| **`CF_WEB_ANALYTICS_BEACON_TOKEN`** | 上一步从 Web Analytics 复制的 **beacon token**（完整一串，勿带引号或多余换行）。 |

以下 workflow 在 **构建 frontend** 时已传入 `VITE_CF_BEACON_TOKEN: ${{ secrets.CF_WEB_ANALYTICS_BEACON_TOKEN }}`：

- `.github/workflows/nightly_vote_refresh.yml`（nightly 部署 Pages 前构建）
- `.github/workflows/monthly_refit.yml`（月度 refit 部署 Pages 前构建）

未配置该 Secret 时，`secrets.CF_WEB_ANALYTICS_BEACON_TOKEN` 为空，构建不会注入 beacon，**不会失败**。

## 4. 部署后验收

### 4.1 浏览器 DevTools

1. 打开线上站点（无痕窗口可减少扩展干扰）。
2. **Network**，筛选 `cloudflareinsights` 或 `rum`。
3. 刷新页面后应看到对 **`beacon.min.js`** 的请求；随后可能有 **`cdn-cgi/rum`** 或同类上报请求。

注意：**广告拦截 / 隐私扩展** 可能静默屏蔽上述请求，此时 **站点功能应正常**；统计会偏少，属预期（见 Phase 20 计划中的风险说明）。

### 4.2 构建产物抽查（可选）

在 CI artifact 或本地执行：

```bash
# 本地模拟 CI（PowerShell 示例）
$env:VITE_CF_BEACON_TOKEN="你的token"
npm run build -w frontend
```

打开 `frontend/dist/index.html`，确认存在：

- `src="https://static.cloudflareinsights.com/beacon.min.js"`
- `data-cf-beacon="{\"token\":\"……\"}"`（HTML 内多为转义后的 `&quot;`）

### 4.3 Cloudflare Web Analytics 面板

部署成功后等待一段时间（官方文档与面板提示为准；常见为 **数分钟至 24 小时**），在 **Web Analytics** 对应站点下查看 PV、地理分布、CWV 等是否开始累积。

## 5. 本地开发（可选）

默认本地 `npm run dev` **可以不配** token（不注入，减少噪音）。

若要在本地构建中验证注入行为，可在仓库根或 `frontend/` 下使用 Vite 惯例的 env 文件（勿提交真实 token）：

- `frontend/.env.local` 中增加一行：  
  `VITE_CF_BEACON_TOKEN=你的token`  
  然后执行 `npm run build -w frontend`。

或将 `.env.local` 加入 `.gitignore`（若尚未忽略），避免误提交。

## 6. 常见问题

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 线上无 `beacon.min.js` | Secret 未配置或名称拼写错误 | 检查 Secret 是否为 **`CF_WEB_ANALYTICS_BEACON_TOKEN`**；重新跑构建部署 |
| Network 无上报 | 广告拦截、企业策略、第三方 Cookie 策略（一般不影响 beacon） | 换浏览器/关扩展试一次；接受统计略低 |
| 面板长期无数据 | 域名与 Web Analytics 站点 hostname 不一致、或流量未到 | 核对 CF 里登记的 hostname 是否与实际访问 URL 一致 |
| 只想关统计 | 删除或清空 Secret，重新构建部署 | 下一版构建将不再注入脚本 |

# P23.5 OG image 验收指南

> **历史资料，不可按此执行。** 本指南只保留已退役的 Today OG 图片、`today.json`、`og-today.png`、`og_today_url` 和旧缓存流程证据；不得运行 `render_og_today.py`、触发相关 `workflow_dispatch`、上传 Today R2 对象或恢复 `/data/og-today.png`。当前电影 OG 入口以 [`docs/system/og-index-worker-contract.md`](../system/og-index-worker-contract.md) 为准；`/today`、`/og/today.png` 和 `/share/today` 必须继续返回 404。

本指南用于验收 **P23.5（Open Graph 卡片 nightly 合成 + index.html meta + 短 TTL 缓存；历史 Today 流程，不可执行）**。
目标是把"是否通过"变成可执行、可复现、可回归的检查项；与 [P23.1 The Movie Today 验收指南](./P23.1%20The%20Movie%20Today%20验收指南.md) 配套使用（P23.5 在 `today.json` 之上再产出一张图片）。

## 1. 验收范围（历史 Today 流程，不可执行）

- `scripts/cron/render_og_today.py`：Pillow 合成 1200×630 `og-today.png`
- `assets/fonts/Inter.ttf` / `assets/fonts/Butler-Medium.ttf` / `Butler-Bold.ttf` + `Inter-OFL.txt` + `README.md`：渲染所需字体与许可
- `scripts/cron/nightly_vote_refresh.py` / `scripts/cron/monthly_refit.py`：在 `today.json` 之后调用 `render_og_today_after_galaxy_export`
- `scripts/cron/upload_galaxy_r2.py`：上传 `og-today.png` 到 R2，并把 `og_today_url` 写入 manifest（`?v=<utc-date>` cache-buster）
- `frontend/index.html`：`og:*` / `twitter:*` meta（含 `image:width`/`image:height`/`image:type`/`image:alt`）
- `frontend/public/_headers`：`/data/og-today.png` 短 TTL（`max-age=300, must-revalidate`）
- `.github/workflows/{nightly_vote_refresh,monthly_refit}.yml`：工件包含 `og-today.png`
- `.gitignore`：本地生成的 `og-today.png{,.tmp}` 不入仓
- `requirements.cpu.txt`：`Pillow>=11.0,<13`
- `scripts/tests/test_render_og_today.py`：12 个单测

## 2. 通过标准（Definition of Done）

以下 9 项全部通过，才算 P23.5 验收通过：

1. 单测全部通过（`scripts/tests/test_render_og_today.py`，12 个用例）。
2. 本地直跑 `render_og_today.py` 写出 1200×630 PNG，文件 ≥50 KB（含真实 poster 时通常 100~250 KB）。
3. 视觉品牌：右下角品牌字使用 **Butler Medium** 且为小写 `the movie cosmos`；URL 为 `the-movie-cosmos.pages.dev`（P23.6 上线自定义域名后替换）。
4. 视觉信息：左侧海报；右侧依次出现 `today's pick · YYYY-MM-DD`（强调色）→ 标题（Inter Bold，最多 2 行+省略号）→ 年份 → 最多 3 个 genre 胶囊（颜色取自冻结调色板）。
5. nightly / monthly workflow 的 artifact 包含 `frontend/public/data/og-today.png`。
6. R2 manifest 出现 `og_today_url`，浏览器直接访问可拿到 `image/png`。
7. Cloudflare Pages（或 GitHub Pages 备线）路径 `/data/og-today.png` 返回 `Cache-Control: public, max-age=300, must-revalidate`。
8. Twitter Card / Facebook Sharing Debugger / opengraph.xyz 等社交验证器能渲染卡片预览，标题=`The Movie Cosmos`，图片即当日 OG 卡片（注意：`og:title` / `twitter:title` 仍为标题字 `The Movie Cosmos`，**只有图内品牌字才是小写**）。
9. Poster 拉取失败时不会覆盖前一日 PNG（atomic rename + entry 返回 `None`）。

## 5. CI / 线上链路验收（历史 Today workflow，不可执行）

> **历史步骤：不可执行。** 不得触发旧 `workflow_dispatch`，不得上传 `og-today.png` 或写入 `og_today_url`；以下内容只保留历史证据。

触发 `.github/workflows/nightly_vote_refresh.yml` 的 `workflow_dispatch`，依次确认：

1. **Job log**：`Run nightly vote refresh` 中能看到  
   - `[render_og_today] today_date=... movie_id=... title=...`  
   - `[render_og_today] wrote tmp=... bytes=... dims=(1200, 630)`  
   - `[render_og_today] finalized ...`
2. **Job log**：`Upload galaxy gzip to R2 (P18.6b)` 中能看到  
   - `[R2] upload key='galaxy/og-today.png' bytes=... content_type=image/png cache_control='public, max-age=300, must-revalidate'`
3. **Artifact**（`galaxy-export-<run_id>` zip）解开后包含 `frontend/public/data/og-today.png`。
4. 部署完成后，访问 manifest 与图片：

   ```text
   https://<domain>/data/galaxy_assets_manifest.json
   https://<domain>/data/og-today.png
   ```

   - manifest 含 `og_today_url`（指向 R2，附 `?v=<utc-date>`）
   - manifest 中 `r2_object_keys.og_today` == `galaxy/og-today.png`（或对应 `R2_KEY_PREFIX`）
   - Pages 路径 `/data/og-today.png` 与 R2 都能拉到同一张 PNG

5. **CDN/Pages 缓存头**（任选其一）：

   ```powershell
   curl.exe -I https://<domain>/data/og-today.png
   ```

   预期 header：
   - `content-type: image/png`
   - `cache-control: public, max-age=300, must-revalidate`

**通过标准**
- CI 全绿；artifact 含 `og-today.png`；manifest 含 `og_today_url` 且可访问；Pages `/data/og-today.png` 短 TTL 命中。

## 6. 社交分享卡片验收（Twitter / Facebook / LinkedIn）

务必使用线上 https URL（本地 dev URL 不会被这些平台抓取）。

### 6.1 opengraph.xyz（最快）

打开 `https://www.opengraph.xyz/url/<URL-ENCODED-DOMAIN>` 或粘贴你的域名根 URL。  
验证：

- "OpenGraph" 一栏显示卡片预览（图 + 标题 + 描述）
- 图片即当日 `og-today.png`
- `og:title = The Movie Cosmos`
- `og:description` 为 P23.5 默认描述
- `og:image:width = 1200`、`og:image:height = 630`

### 6.2 X (Twitter) Card Validator

入口：`https://cards-dev.twitter.com/validator`（需 X 登录；若无访问，可改用 X 客户端把链接发到自己的 Drafts/DM 看缩略图）

- `twitter:card` 应为 `summary_large_image`
- 图片预览为当日 OG 卡

### 6.3 Facebook Sharing Debugger

入口：`https://developers.facebook.com/tools/debug/`，粘贴 URL 后点 "Scrape Again"。

- "When this URL was shared on Facebook, the following information was found"
- og:image 显示当日卡片

### 6.4 隔日刷新

T 日记录 `og-today.png` 的 md5；T+1 日（UTC 跨日 + nightly 跑过之后）再请求一次：

```powershell
curl.exe -s -o og.before.png https://<domain>/data/og-today.png; (Get-FileHash og.before.png).Hash
# … 等到下一次 nightly 跑完 …
curl.exe -s -o og.after.png https://<domain>/data/og-today.png; (Get-FileHash og.after.png).Hash
```

**通过标准**
- 三家 validator 至少 2 家显示当日卡片；
- T 与 T+1 的 md5 不同（即 nightly 真的换图了）。

## 7. 失败场景验收（建议至少覆盖 2 项）

| 场景                           | 操作                                                                                          | 预期日志 / 行为                                                                                            |
| ------------------------------ | --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| A. 缺 `today.json`             | 删除 `frontend/public/data/today.json` 后跑 `render_og_today_after_galaxy_export`             | `WARN today.json missing ...; skip`，函数返回 `None`，不改写 `og-today.png`                                |
| B. 缺 `galaxy_data.json`       | 删除 `frontend/public/data/galaxy_data.json` 后跑入口                                         | `WARN galaxy_data.json missing ...; skip`，返回 `None`                                                     |
| C. `today.movie_id` 不在 movies | 把 `today.json` 的 `movie_id` 改成不存在 ID 后跑入口                                          | `ERROR rendering OG card: movie_id=... not found in ...`，返回 `None`，前一日 PNG 不变                     |
| D. Poster 拉取失败             | 见 4.4（用 mock 或 hosts 屏蔽）                                                               | `ERROR rendering OG card: ...`，返回 `None`，前一日 PNG 不变                                               |
| E. 缺 Butler 字体              | 临时把 `assets/fonts/Butler-Medium.ttf` 重命名后跑命令行                                      | 控制台 `WARN Butler not found ...; brand falls back to Inter Medium`，PNG 仍生成（视觉降级，不算 4.3 通过）|
| F. 缺 Inter 字体               | 临时把 `assets/fonts/Inter.ttf` 重命名后跑命令行                                              | `WARN Inter not found ...; falling back to default font`，使用 Pillow 默认 DejaVu，PNG 仍生成              |

**通过标准**
- 任意 2 项覆盖到，整套脚本不抛未捕获异常，且 A/B/C/D 场景下**前一日 og-today.png 字节内容保持不变**。

## 8. 失败判定与快速定位

| 现象                                                | 判定         | 优先检查                                                                                                                            |
| --------------------------------------------------- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| `og-today.png` 未生成                               | 不通过       | `nightly_vote_refresh.py` / `monthly_refit.py` 是否在 `write_today_json_after_galaxy_export` 之后调用 `render_og_today_after_galaxy_export` |
| manifest 无 `og_today_url`                          | 不通过       | `upload_galaxy_r2.py` 是否检测到 `og-today.png`（`og_today_png.is_file()` 分支）                                                    |
| social validator 报错或显示老图                     | 部分通过     | 短 TTL 头是否生效；validator 是否要求 re-scrape；CDN 是否真的拿到新文件                                                             |
| 字体 fallback 警告（Butler / Inter not found）      | 4.3 不通过   | `assets/fonts/` 是否完整提交；FreeType 是否支持 variation；`Pillow>=11.0` 是否安装                                                  |
| poster fetch 报 timeout / 403                       | 看是否兜底   | 网络/代理；TMDB 临时不可用 → 由 atomic rename 兜底，前一日 PNG 保留即可                                                             |
| PNG 远超 300KB                                      | 关注但不阻塞 | poster 异常大；可考虑后续把 `optimize=True` 升级为 `optimize=True, compress_level=9`                                                |
| 卡片在 X 上裁切异常                                 | 不通过       | `twitter:card=summary_large_image` 是否设置；图比例是否 1.91:1（1200×630 ✓）                                                        |

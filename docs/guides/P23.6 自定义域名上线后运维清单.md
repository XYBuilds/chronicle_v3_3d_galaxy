# P23.6 自定义域名上线后运维清单

> **历史资料，不可按此执行。** 本指南保留旧 Today OG 图片和 `/data/og-today.png` 运维证据；不得运行或恢复 `og-today.png`、`today.json`、`today_url`、Today R2/cache 或相关分享流程。当前电影 OG 路由、fallback 和退役 Today surface 以 [`docs/system/og-index-worker-contract.md`](../system/og-index-worker-contract.md) 为准。

本指南面向**已**在 Cloudflare Pages 绑定生产自定义域名（例如 `themoviecosmos.com` / `www.themoviecosmos.com`）且仓库内 `frontend/index.html` 的 `og:*` / `twitter:image` 已指向该域之后的**控制台与验收步骤**。代码侧 hostname 以 `README.md` 与 `frontend/index.html` 为准；此处只列**仍需在 Cloudflare / 浏览器完成**的事项。

**生产发布路径（与自定义域无关，但易与 §6 混淆）**：线上 **Cloudflare Pages 应用壳**的更新应由 **GitHub Actions** 调用 **`cloudflare/wrangler-action@v3`** 对 **`frontend/dist`** 做 **Direct Upload**；大体积 **`galaxy_data.json.gz` / `galaxy_search_index.json.gz` 在 R2**，见 [`TMDB 电影宇宙 Data Pipeline.md`](../project_docs/TMDB%20电影宇宙%20Data%20Pipeline.md) §12 与 [P24.1 实施报告](../reports/Phase%2024.1%20P24.1%20Cloudflare%20R2%20发布链路清理%20实施报告.md)。**不要**把 Cloudflare Pages 与仓库 **Git 自动构建**当作生产入口（默认分支 merge 若触发该路径，可能未跑本仓库约定步骤并误校验大文件）。

---

## 0. 你要达成的结果

全部勾选后应满足：

1. 浏览器从 **`https://themoviecosmos.com/`**（及若使用的 **`https://www.themoviecosmos.com/`**）加载站点 **HTTP 200**，证书有效。
2. 从上述源站发起的 **`galaxy_data.json.gz`**（经 `galaxy_assets_manifest.json` 指向的 R2 或其它公网 URL）请求 **无 CORS 报错**（DevTools Console 无红色 CORS 相关错误；Network 中该请求状态为 200）。
3. 社交爬虫抓取首页时，`og:image` / `twitter:image` 使用**生产绝对 URL**（与 `index.html` 一致），且图片可 **200** 拉取。
4. （可选）若启用 **301**：访问 `https://the-movie-cosmos.pages.dev/` 会跳到主域，避免与主域重复收录。
5. （可选）**Web Analytics**：新 hostname 在 Cloudflare 统计面板中可见流量（或已按控制台说明并入现有 site）。

## 1. R2：CORS 允许新 Origin（必做）

大 JSON 经 manifest 从 **R2 公网域**加载时，浏览器会做 **跨域** 检查。仅绑定 Pages 自定义域**不会**自动改 R2 CORS，必须在 bucket 侧显式加入生产源。

1. 登录 [Cloudflare Dashboard](https://dash.cloudflare.com/) → **R2** → 选中你的 **bucket**（与 GitHub Secret `R2_BUCKET` 一致）。
2. 进入 **Settings** → **CORS policy**（名称以当前 UI 为准）。
3. 在 **AllowedOrigins**（或等价字段）中至少包含：
   - `https://themoviecosmos.com`
   - `https://www.themoviecosmos.com`（若你在 Pages 上绑定了 `www`）
   - `https://the-movie-cosmos.pages.dev`（保留 Pages 默认域作备线时的跨域拉取）
4. 若仍需本地 `vite preview` 直连 R2 验证，可继续保留：
   - `http://127.0.0.1:4173`
5. **AllowedMethods** 至少：`GET`、`HEAD`。Headers 按默认或沿用现有策略即可。

更完整的背景与 JSON 示例见 [`P18.6b Cloudflare R2 上线操作手册.md`](./P18.6b%20Cloudflare%20R2%20上线操作手册.md) §1.3。

**验收**：用主域打开站点 → **F12 → Console** 无 CORS 错误；**Network** 中 `galaxy_data.json.gz`（或 manifest 中的 gzip URL）为 **200**。

## 2. Cloudflare Pages：自定义域与 TLS（你已绑定则复核）

若 **Custom domains** 中 apex 与 `www` 均已 **Active** 且 **SSL enabled**，本节仅需偶尔复核：

- DNS 变更、证书续期、或误删域名后，回到 **Workers & Pages** → 你的项目 → **Custom domains** 查看状态。

---

## 3. 可选：`*.pages.dev` 301 到主域（SEO）

仓库已提供 **`frontend/functions/_middleware.js`**：仅当 Host 为 **`the-movie-cosmos.pages.dev`**（不含分支预览子域）时 **301** 到 **`https://themoviecosmos.com`** 同路径与 query。CI 里 **`cloudflare/wrangler-action`** 已设 **`workingDirectory: frontend`** 且命令为 **`pages deploy dist`**，这样 Wrangler 的默认 **`./functions`** 与 **`dist`** 均相对 `frontend/`，中间件会随部署打包；若在仓库根目录执行 `pages deploy frontend/dist` 且不设 `workingDirectory`，则不会带上 `frontend/functions/`。

若未使用该中间件、或希望改在边缘统一治理，可在 Cloudflare 侧配置**重定向**（具体菜单位置以当前产品为准，常见为 **Bulk Redirects** 或 **Rules → Redirect Rules**）：

- **源**：`the-movie-cosmos.pages.dev`（或完整 `https://the-movie-cosmos.pages.dev/*`）
- **目标**：`https://themoviecosmos.com$1`（或控制台要求的等价写法）
- **状态码**：**301**

若你希望 **备线仍可长期用 pages.dev 访问**（不重定向），可跳过本节；与 `README.md` §6 说明一致即可。

---

## 4. Web Analytics：把新 hostname 纳入统计（可选）

代码侧 beacon 由构建时 **`VITE_CF_BEACON_TOKEN`** 注入（见 [`P20.5 Cloudflare Web Analytics 接入操作指南.md`](./P20.5%20Cloudflare%20Web%20Analytics%20接入操作指南.md)）。自定义域上线后：

1. 打开 **Analytics → Web Analytics**（或账户内 **Web Analytics** 入口）。
2. 找到已为 Pages 创建的 **site**，按控制台说明将 **`themoviecosmos.com`**（及 **`www.themoviecosmos.com`**，若需要分开展示）加入 **hostnames** / 站点列表（UI 文案以 Cloudflare 为准）。
3. **无需**更换 beacon token，除非你在控制台主动轮换 token（轮换后需更新 GitHub Secret `CF_WEB_ANALYTICS_BEACON_TOKEN` 并重新部署一次带前端的 workflow）。

**验收**：无痕窗口访问主域 → Network 中仍有 `beacon.min.js` / rum 相关请求（勿被广告拦截插件误判为全部失败）；24h 内在 Web Analytics 面板中能看到新 hostname 流量。

## 5. OG / Twitter 卡片验收（历史 Today OG 步骤不可执行）

> **历史步骤：不可执行。** 下方 `/data/og-today.png`、短 TTL 和隔日 Today 重绘只记录旧行为；不得执行或恢复。

1. **直链图片**（确认 CDN / Pages 返回 PNG 与短缓存头）：

   ```powershell
   # 历史 Today 命令：不可执行。
   curl.exe -I "https://themoviecosmos.com/data/og-today.png"
   ```

   期望：`content-type` 含 `image/png`；`cache-control` 含较短 `max-age`（与 `frontend/public/_headers` 中 `/data/og-today.png` 策略一致）。

2. **元数据**：用 [opengraph.xyz](https://www.opengraph.xyz/) 或各平台官方 **Card / Sharing Debugger**，输入 **`https://themoviecosmos.com/`**，确认 `og:title`、`og:image`、`og:url` 与线上 `index.html` 一致且预览正常。

3. **隔日更新**：`og-today.png` 由 nightly 按当日 `today.json` 重绘；社交平台可能缓存旧图；调试工具通常提供 **重新抓取**；短 TTL 有助于后续自然更新。

更细的脚本与 CI 验收见 [`P23.5 OG image 验收指南.md`](./P23.5%20OG%20image%20验收指南.md)。

## 6. 合并代码与部署后快速自检

1. 将包含 `frontend/index.html` 新域名的变更合并进默认分支后，**等待或手动触发**会 **构建 `frontend/dist` 并以 wrangler Direct Upload 发布到 Cloudflare Pages** 的 **GitHub Actions** workflow（如 **`nightly_vote_refresh.yml`**、**`monthly_refit.yml`**，或团队单独维护的发布 workflow）。**不**依赖 Cloudflare 控制台「Git 连接 → 自动构建 Pages」作为生产更新入口；若该 Git 路径仍启用，应在控制台对其 **Disconnect / 禁用生产部署**，避免与 GHA 双轨冲突及 25MiB 静态校验问题（背景见 [P18.6 Cloudflare Pages 切换操作指南](./P18.6%20Cloudflare%20Pages%20%E5%88%87%E6%8D%A2%E6%93%8D%E4%BD%9C%E6%8C%87%E5%8D%97.md) §1 与 [P24.1 实施报告](../reports/Phase%2024.1%20P24.1%20Cloudflare%20R2%20发布链路清理%20实施报告.md)）。
2. 部署完成后：
   - 打开主域首页，完成一次 **Loading → Cover** 路径；
   - 随机点选进入 focus，确认 drawer 与星系交互正常。

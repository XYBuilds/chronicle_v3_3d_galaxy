# P26.1 HDR 与色彩验证测试指南

本指南对应 Phase **P26.1**（见 `.cursor/plans/phase_26_device_spatial_optimization.plan.md`）：在 **Mac / Windows**、**HDR 开/关**、**多浏览器** 下，系统化对比 **idle / active 星点**、**focus Perlin 球**、**rating reference**、**cover / loading 品牌字**、**drawer / HUD 白边与边框**，并尽量区分偏色来自 **CSS OKLCH token**、**WebGL sRGB 输出**、**系统/浏览器 HDR 色彩管理**，还是 **显示器 / 截图链路**。

结论与矩阵表可归档到：`docs/reports/Phase 26.1 P26.1 HDR 色彩验证矩阵 实施报告.md`。

---

## 1. 本指南回答什么

跑完一次完整矩阵后，应能书面回答：

1. **idle 与 active 的色差**是否在多环境下稳定复现？是否仅在某一种 HDR 或浏览器组合上出现？
2. **DOM（HUD）** 与 **WebGL（星场 / Perlin）** 是否「各走各的」：例如 HUD 与 CSS 色块一致，但星点异常，则更指向 WebGL / 合成链路。
3. **WebGL 中心 `readPixels` 数值** 与肉眼看到的背景/星场是否一致：若读数是预期黑/近黑而屏幕发灰，则更指向显示与色彩管理，而非 shader 写错。
4. 是否需要进入 **改 token / 改 shader** 阶段（P26.1 结论）；本阶段**不**凭单设备主观感受直接改全局色。

## 3. 查询参数速查

以下参数可组合在同一 URL 中（`&` 连接）。

| --- | --- | --- |
| `p26ColorAudit` | `1` / `true` / `yes` | 主场景加载完成后，左下角显示 **P26.1 color audit** 浮层（英文 QA 文案，不进产品 i18n）。 |

## 4. 内置工具：P26.1 color audit 浮层

在满足 `p26ColorAudit` 且应用进入 **主场景**（数据与索引就绪、Cover 流程已 gate）后，左下角出现浮层，包含：

### 4.1 CSS 变量色块（DOM 侧）

与 `frontend/src/index.css` 中 HUD / 宇宙背景相关 token 对齐，用于判断 **OKLCH + 主题** 在当台显示器上的呈现：

- `--foreground`、`--border`、`--muted-foreground`、`--background`、`--ring`
- `--cosmos-brand-muted`、`--cosmos-universe-bg`
- `--ui-edge-canvas-color`（悬停环 / Timeline 等压在 canvas 上的细线色）

**怎么看**：若 HUD 文字/描边与对应色块 **明显不一致**，先怀疑 **叠加层透明度、backdrop、或截图压缩**；若 **色块之间相对关系** 与 Figma/设计预期不符，再怀疑 **主题或 token**。

### 4.2 纯 sRGB 平面参考

浮层内三个硬编码色块：`#FFFFFF`、`#808080`、`#000000`。

**怎么看**：若 OKLCH 灰阶与 sRGB 参考 **在 HDR on/off 下相对变化不一致**，提示 **色彩管理或 EOTF** 介入；若仅 WebGL 区域异常而 sRGB 块稳定，提示问题更可能在 **WebGL 合成或后处理**。

### 4.3 Sample WebGL center RGBA

点击按钮后，对带 `data-galaxy-webgl="1"` 的主 WebGL2 canvas 执行 **`readPixels`**，采样 **帧缓冲中心** 一个像素（坐标为 WebGL 惯例：**原点在左下**；实现里使用 `floor((w-1)/2)`、`floor((h-1)/2)`）。

**典型预期**

- 宏观 idle、背景以黑为主时，中心常接近 **`#000000` 或极低 RGB**；若 Perlin / 高亮占满中心则读数会非黑，属正常。
- 该读数是 **线性管线写入、按当前输出色彩空间解释后的字节**，工程上约定为 **Three.js `SRGBColorSpace`**（见 `frontend/src/three/scene.ts`）。

**限制（必读）**

- 读的是 **当前默认 FBO** 在点击时刻的内容；若 Bloom / 后处理写入离屏缓冲再合成，读数可能 **不** 等于肉眼最终像素；此时读数仍有助于对比「GPU 出口」与「屏幕」差异。
- 需在 **场景已挂载、canvas 存在** 后再点；否则会提示无 WebGL canvas。
- 不要在 **隐私模式严格限制 WebGL** 的浏览器配置下强依赖该按钮。

### 4.4 `dynamic-range: high` 一行

浮层展示 `matchMedia('(dynamic-range: high)')` 是否匹配。  
这表示浏览器报告的 **高动态范围能力倾向**，**不等于** 操作系统「HDR 显示」开关的权威状态；仍以你在系统设置里记录的 HDR on/off 为准。

## 6. 每一步操作清单（每台机器）

### 6.1 环境登记（1 分钟）

在记事本或报告表格中写下：

- 日期、测试人
- 操作系统版本、浏览器版本
- HDR：开/关；若 macOS 为「参考模式」或 Windows 为「自动 HDR」等子选项，写明
- 显示器：型号、分辨率缩放、内建/外接

### 6.2 打开基准 URL

使用第 3 节 URL，确认：

- 无控制台 **红色** 报错；若有 `[P26.1] today override id not in bundle`，更换 `todayMovieId`。
- 左下角出现 **P26.1 color audit**。

### 6.3 Cover 阶段（固定影片时）

观察 **cover / loading 品牌字**（`--cosmos-brand-muted` 等与浮层色块对照）：

- 与浮层中 `--cosmos-brand-muted`、`--cosmos-universe-bg` 色块对比，记录 **偏暖/偏冷/发灰/发糊** 等主观词 + 是否仅在 HDR on 出现。

### 6.4 进入星系 idle

- **Idle 星点**：整体色调、白点是否发青/发黄；与 sRGB 灰阶块对比亮度感。
- 点击 **Sample WebGL center RGBA**，复制读数到表格。

### 6.5 Hover / active（不进入 focus 也可先做）

- 悬停使某星进入 **active** 高亮，观察与 **idle** 的色差是否符合预期。
- 若怀疑仅 bloom：可对比 **星点核心** vs **光晕边缘**（主观描述即可）。

### 6.6 Focus：Perlin + rating reference

从 cover **Enter** 或从 idle 点选同一影片进入 **focus**：

- **Perlin 球**：高光与暗部是否「洗白」或「压黑」。
- **FocusL rating reference**（若可见）：与浮层 `--foreground` / `--muted-foreground` 对比。
- 再次 **Sample WebGL center**（此时中心可能被球或高光占据），记录读数与画面内容说明（避免误读为「黑场异常」）。

### 6.7 HUD：drawer、搜索条、顶栏

打开 **Info**、**Drawer**、看 **SearchBar** 与右上角图标区：

- 白字/灰字与浮层 token 色块对齐度。
- **细边框**（`--border`、`--ui-edge-canvas-color`）在 HDR on 下是否发糊或过亮。

### 6.8 截图命名建议

便于归档：

```text
P26.1_<OS>_<Browser>_HDR-<on|off>_<scene>-<idle|focus|hud>.png
```

## 8. 简易判定思路（非绝对）

```text
HUD 与 CSS 色块一致，WebGL 区域异常
  → 优先查 WebGL 输出、合成、后处理、与 HDR 下窗口缓冲格式。

HUD 与 CSS 色块已不一致
  → 优先查主题、OKLCH 在当浏览器的计算、以及 OS 级色彩滤镜。

readPixels 合理但肉眼发灰/发绿
  → 优先查显示器、HDR、截图软件色彩描述文件。

仅 Safari 或仅 Chrome
  → 记为「浏览器差异」，避免在另一浏览器上「修假问题」。
```

## 附录 A：从 Windows 通过 SSH 登录 Mac

P26.1 需要在 **本机 Mac 屏幕** 上跑 Safari、看 HDR 与色彩；你仍可在 **Windows** 上改代码、开 PR。下面说明如何从 **Windows 终端** SSH 到 **同一台或可路由的 Mac**，便于在 Mac 上执行 `git pull`、`npm run dev` 等。**WebGL / HDR 的主观对比必须在 Mac 显示器上完成**；SSH 只解决「远程敲命令」，不替代本机浏览器验收。

### A.1 在 Mac 上打开 SSH（远程登录）

1. 打开 **系统设置** → **通用** → **共享**（较旧系统：**系统偏好设置** → **共享**）。  
2. 打开 **远程登录（Remote Login）**。  
3. 在允许的用户列表中勾选你的 **Mac 本地账户**（建议不要长期勾选「所有用户」，除非内网隔离可信）。  
4. 记下窗口里类似 `ssh yourname@Mac-mini.local` 的提示；或在 Mac **终端** 执行 `hostname` 查看主机名，执行 `ipconfig getifaddr en0`（常见 Wi‑Fi）或 `en1` 等查看 **局域网 IPv4**，例如 `192.168.1.23`。

**防火墙**：若 Mac 防火墙拦截入站，在 **系统设置** → **网络** → **防火墙** → **选项** 中允许 **远程登录（sshd）** 接受传入连接。

### A.2 在 Windows 上使用 SSH（OpenSSH 客户端）

**Windows 10 / 11** 通常已自带 OpenSSH。在 **PowerShell** 或 **Windows Terminal** 中执行：

```powershell
ssh <mac用户名>@<Mac的IP或主机名>
```

示例：

```powershell
ssh alice@192.168.1.23
ssh alice@Mac-mini.local
```

首次连接会提示 **主机密钥指纹**，核对后输入 `yes`，再输入 **Mac 该用户的登录密码**（不是 Apple ID 密码，除非二者相同）。

**若提示找不到 `ssh` 命令**：以管理员打开 PowerShell，安装客户端可选组件：

```powershell
Add-WindowsCapability -Online -Name OpenSSH.Client~~~~0.0.1.0
```

或安装 [Git for Windows](https://git-scm.com/download/win)，使用 **Git Bash** 里的 `ssh`。

### A.3 可选：SSH 公钥登录（少输密码）

在 **Windows** 上生成密钥（若已有可跳过）：

```powershell
ssh-keygen -t ed25519 -C "win-p26" -f $env:USERPROFILE\.ssh\id_ed25519_mac
```

把公钥安装到 Mac（仍可用密码登录一次时执行；将路径与地址换成你的）：

```powershell
type $env:USERPROFILE\.ssh\id_ed25519_mac.pub | ssh alice@192.168.1.23 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

在 Windows 用户目录下编辑 `C:\Users\<你>\.ssh\config`（没有则新建），例如：

```sshconfig
Host mac-p26
    HostName 192.168.1.23
    User alice
    IdentityFile ~/.ssh/id_ed25519_mac
```

之后可直接：`ssh mac-p26`

### A.4 SSH 登录后在 Mac 上常做的事

```bash
cd /path/to/chronicle_v3_3d_galaxy
git pull
npm install
npm run dev -w frontend
```

默认 Vite 只监听 **localhost**，适合你在 **Mac 本机 Safari/Chrome** 打开 `http://localhost:5173/?p26ColorAudit=1&...` 做色彩矩阵。若必须从 **另一台设备** 用浏览器访问 Mac 上的 dev server，需要让 Vite 监听 `0.0.0.0`（例如 `vite --host`，具体以项目脚本为准），并自行限制 **仅内网**、配合 Mac 防火墙；**HDR / Safari 仍以 Mac 本机屏为准**。

**可选**：在 Windows 上安装 **VS Code** 的 **Remote - SSH** 扩展，用 **Remote-SSH: Connect to Host…** 打开 Mac 上的仓库文件夹，集成终端即在 Mac shell 中，流程与上相同。

### A.5 用 scp 传截图或笔记（Windows → Mac 或反向）

### A.6 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| `Connection refused` | Mac 未开启「远程登录」或端口被挡 | 复查 **共享 → 远程登录**；公司网络是否禁止 **22/tcp** |
| `Permission denied` | 用户名错；或仅允许密钥 | 使用 Mac **短用户名**（系统设置 → 用户与群组）；检查 `~/.ssh/authorized_keys` 权限为 `600`、目录 `700` |
| 连接超时 | 不在同一网段、Wi‑Fi AP 隔离、VPN | 换同一路由器网段；试 Mac 热点；向网络管理员确认隔离策略 |
| `Could not resolve hostname` | `.local` 跨网段 / mDNS 不可用 | 改用 **IPv4 地址** |
| 能 SSH 但浏览器打不开 dev | 只绑定了 localhost | 在 Mac 本机浏览器用 `http://127.0.0.1:5173`；或按 A.4 配置 `--host`（注意安全边界） |

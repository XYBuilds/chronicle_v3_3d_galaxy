# P34.3 OG Index KV 上线操作指南

> **Disposition:** supporting reference only (safe operating material for Chronicle producer ops). Contract truth: [`docs/system/og-index-worker-contract.md`](../system/og-index-worker-contract.md).

本指南定义 **Phase 40.6 之后** 的 OG 索引日常运维。它只覆盖电影 OG：KV 中的影片记录和当前 galaxy 版本。当前跨仓兼容规则以 [`docs/system/og-index-worker-contract.md`](../system/og-index-worker-contract.md) 为准；本指南只保留 Chronicle producer 的操作入口。品牌首页 OG 与 `/movie/:id` 动态 OG 保留；`/today`、`/today?*`、`/og/today.png` 均是不支持的 404。

> **历史边界**：schema v1、KV `today`、`today.json`、Today OG、Today R2/cache 对象和相应发布流程已经退役，不能作为日常操作、回滚方案或故障恢复手段。涉及 v1→v2 迁移或远端遗留对象删除的操作仅可在 **Phase 40.8 人工 Gate** 中执行，并须另行授权。

## 1. 当前索引契约

Writer 的已提交 checkpoint 是 R2 `ops/og-index/state-v2.json.gz`：gzip JSON、`schema_version: 2`、`projection_version: "og-index-v2"`，并以 `Cache-Control: no-store` 上传。它仅记录 movie projection hashes 与 `meta_g_value`。

KV namespace `OG_INDEX` 只允许以下键：

| Key | 值 | 用途 |
| --- | --- | --- |
| `movie:{id}` | `{"title","release_date","genres","poster_url"}` | 单部影片的最小 OG 元数据 |
| `meta:G` | galaxy data 的 `meta.version` 字符串 | 电影 OG 的全局版本标识 |

不得写入 `today`，也不得把选择、评分、热度、坐标、HUD locale 或查询参数加入影片 projection。Worker 只读取 `movie:{id}` 和 `meta:G`；它不提供 Today 路由或 Today PNG。

## 2. 同步规则

nightly 与 monthly workflow 均在导出并验证 galaxy 数据后运行 v2 增量同步。日常流程固定为：

```text
export galaxy → validate → sync OG index v2 → upload R2 galaxy assets → build frontend → deploy static site
```

同步按以下顺序进行：

1. 写入变化的 `movie:{id}`；
2. 删除不再存在的 `movie:{id}`；
3. read-back 本次变更和删除结果；
4. 写入并 read-back 验证 `meta:G`；
5. 成功后覆盖 `state-v2.json.gz`。

checkpoint 缺失、损坏、KV 写入失败、read-back 不一致或配额超限时必须 fail closed：不得发布、不得自动 bootstrap、不得回退为全量同步，也不得创建任何 Today 记录。下一次运行从上一个已提交的 v2 checkpoint 幂等重放。

默认配额由 `OG_INDEX_MAX_PUTS=900`、`OG_INDEX_MAX_DELETES=900` 控制；任何超限在首笔写入前失败。`OG_INDEX_KV_BATCH_SIZE` 默认 `1000`，不得超过 API 支持的上限。

## 3. 初次启用与恢复边界

常规 scheduled workflow 只接受已验证的 v2 checkpoint。首次创建 v2 checkpoint 或灾难恢复都不是 scheduled 工作：须由负责人明确批准，在人工窗口审查远端 keyset、candidate v2 snapshot 和预计差异后执行。

如现有环境仍停留在 v1，迁移顺序为：验证 candidate v2 → 应用并 read-back movie delta → 删除 KV `today` 并 read-back 确认缺失 → 最后写入或核对 `meta:G` → 提交 v2 checkpoint。任一步失败都不得推进 checkpoint，也不得删除 v1。v1 只能在这项显式 Phase 40.8 人工 Gate 中读取，不能被日常 writer 继续使用；scheduled v2-only 同步不触碰 `today`。

KV `today`、遗留 R2 Today 对象和缓存的删除同样属于 Phase 40.8 人工 Gate。它们既不是 v2 同步的输入，也不是可自动执行的清理步骤。若 OG 服务发生故障，恢复路径是修复 v2 movie projection、KV 凭据或 Worker/静态站点配置；**不得恢复 Today 生成、上传或路由**。

## 4. 配置与权限

KV writer 需要以下 CI secrets：

| Secret | 说明 |
| --- | --- |
| `CLOUDFLARE_ACCOUNT_ID` | Cloudflare account ID |
| `OG_INDEX_KV_NAMESPACE_ID` | `OG_INDEX` namespace ID |
| `OG_INDEX_KV_API_TOKEN` | 仅具 Workers KV Storage Edit 的 token |
| `R2_ACCOUNT_ID` / `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` / `R2_BUCKET` | 读取和提交 checkpoint 所需的 R2 凭据 |

Token 不需要 Pages 权限；不要以 R2 S3 key 访问 KV。workflow 缺少任何必需凭据必须失败，不能跳过同步或改用旧索引格式。

本地检查可使用不提交的 `.env`：

```env
CLOUDFLARE_ACCOUNT_ID=your_account_id
OG_INDEX_KV_NAMESPACE_ID=your_namespace_uuid
OG_INDEX_KV_API_TOKEN=your_kv_api_token
# OG_INDEX_MAX_PUTS=900
# OG_INDEX_MAX_DELETES=900
# OG_INDEX_KV_BATCH_SIZE=1000
```

## 5. 日常验证

每次 scheduled run 必须输出 `OG_INDEX_SUMMARY`，其中只计入 movie PUT、movie DELETE 与 `meta:G`。发布前确认：

- checkpoint 为 `ops/og-index/state-v2.json.gz`，`schema_version` 为 2、`projection_version` 为 `og-index-v2`；
- summary 不含 `today` 或 Today 控制键；
- 变更影片的 read-back 与 projection 一致；
- `meta:G` 与当前 galaxy `meta.version` 一致；
- 静态构建产物不含 `today.json`、Today manifest 字段或 Today OG；
- `/today`、带任意 query 的 `/today`，以及 `/og/today.png` 返回 404；
- `/` 在 galaxy data 与搜索索引到达终态后进入 idle，`/movie/:id` 仍可生成电影 OG 和深链页面。

本地无凭据测试不得访问 Cloudflare：

```powershell
python -m pytest scripts/tests/test_og_pipeline_phase34.py scripts/tests/test_og_index_state.py scripts/tests/test_og_index_snapshot_r2.py scripts/tests/test_sync_og_index_kv.py
```

## 6. 故障处理

| 现象 | 处理 |
| --- | --- |
| v2 checkpoint 缺失或无效 | 停止 scheduled 发布；在人工 Gate 中审查并建立/恢复 v2 checkpoint。 |
| KV 403 | 核对 `OG_INDEX_KV_API_TOKEN` 的 Workers KV Storage Edit 权限。 |
| KV 404 | 核对 namespace ID、account ID 和 Worker 绑定。 |
| `OG_INDEX_QUOTA_EXCEEDED` | 审查 movie delta 和 summary；不要在 scheduled 中绕过限额。 |
| movie OG 过期或缺失 | 修复对应 `movie:{id}` projection 与 `meta:G`，执行受控 v2 同步。 |
| Today URL 被请求 | 保持 404；不得生成、上传或缓存 Today 内容。 |

## 7. Worker 对齐

Worker 使用同一 `OG_INDEX` namespace，读取 `movie:{id}` 与 `meta:G`。电影 PNG 版本可基于 `G` 与电影 projection 计算。Worker 与静态托管边界必须保留 `/today`、`/today?*`、`/og/today.png` 的 404，不得通过 SPA fallback、KV 回退或缓存重写使其复活。

# P34.3 OG Index KV 上线操作指南

本指南是 **Phase 34.3** 的运维侧清单：把社交预览所需的**影片元数据索引**写入 Cloudflare KV（`OG_INDEX` namespace），并**停用** nightly 静态 `og-today.png` 管线。

**背景与计划 SSOT**：`.cursor/plans/phase_34_social_preview_distribution.plan.md` §34.3。  
**前置阅读**（Cloudflare 账号与 CI 已具备时）：

- [P18.6 Cloudflare Pages 切换操作指南](./P18.6%20Cloudflare%20Pages%20切换操作指南.md) — `CLOUDFLARE_ACCOUNT_ID` / `CLOUDFLARE_API_TOKEN`
- [P18.6b Cloudflare R2 上线操作手册](./P18.6b%20Cloudflare%20R2%20上线操作手册.md) — nightly/monthly 主链路顺序
- [P34.2 静态 OG 基线审计](../reports/Phase%2034.2%20P34.2%20静态%20OG%20基线审计%20实施报告.md)（可选）— 切换前现状

**与 P23.5 的关系**：P23.5 的 `render_og_today.py` → `og-today.png` 在 **34.3 起不再被 nightly/monthly 调用**，也不再上传 R2。脚本仍保留在仓库内供回滚；社交图 PNG 改由 **Phase 34.4 Worker** 动态生成（本指南只负责 **KV 索引**，不负责 Worker 部署）。

## 0. 完成后应达到的状态

| # | 结果 |
|---|------|
| 1 | Cloudflare 上存在 KV namespace（建议命名 **`OG_INDEX`**），并已拿到 **Namespace ID**。 |
| 2 | GitHub Actions Secrets 含 **`OG_INDEX_KV_NAMESPACE_ID`**，与现有 **`CLOUDFLARE_ACCOUNT_ID`**、**`CLOUDFLARE_API_TOKEN`** 同账号可用。 |
| 3 | **至少一次**执行 `--scope full`，KV 内存在全量 `movie:{id}`（约 6 万条）+ `meta:G` + `today`。 |
| 4 | nightly 日志在 export 后出现 `[og_index_kv] done keys_written=2`（`daily` 范围）或明确 skip（Secrets 未配时）。 |
| 5 | monthly 日志在 export 后出现 `[og_index_kv] done keys_written=<N>`（`N` ≈ 电影数 + 2）。 |
| 6 | R2 manifest **不再**含 `og_today_url`；CI artifact **不再**打包 `og-today.png`。 |
| 7 | （34.4 之后）独立 Worker 绑定同一 KV namespace，能 `GET` 到 `movie:{id}` / `today` / `meta:G`。 |

**尚未由 34.3 解决**（留给后续 Phase）：

- 浏览器 `index.html` 仍可能指向 `/data/og-today.png` → **34.6**
- `/movie/:id` 爬虫 meta 注入 → **34.5**
- 动态 PNG `/og/*` → **34.4**

## 1. KV 里存什么（键约定）

Worker（34.4）与主仓脚本共用下列约定：

| Key | 值类型 | 内容 |
|-----|--------|------|
| `meta:G` | 纯字符串 | `galaxy_data.json` → `meta.version`（与 R2 manifest `data_version` 对齐，如 `2026.05.10.daily.30`） |
| `today` | JSON 对象 | `{"date":"YYYY-MM-DD","movie_id":number}`，来自 `frontend/public/data/today.json` |
| `movie:{id}` | JSON 对象 | `{"title","release_date","genres","poster_url"}` — 仅 OG 所需最小字段 |

**不写入 KV 的内容**：overview、多语言 HUD 文案、`lang` query、`vote_count` 等（见 Phase 34 计划 §内容身份）。

**同步范围（脚本行为）**：

| 触发方 | `scope` | 写入的键 |
|--------|---------|----------|
| `nightly_vote_refresh.py` | `daily` | `meta:G`、`today` |
| `monthly_refit.py` | `full` | `meta:G`、`today`、全部 `movie:{id}` |
| 手动 CLI（首次 / 补数） | `full` | 同上 |

> **重要**：Worker 上线前必须至少跑通一次 **`full`**，否则 KV 里没有 per-movie 记录，`/og/movie/{id}.png` 会全部走品牌 fallback。

## 2. Cloudflare 控制台：创建 KV namespace

1. 登录 [Cloudflare Dashboard](https://dash.cloudflare.com/) → 选择 **The Movie Cosmos** 使用的同一 Account。
2. 左侧 **Workers & Pages** → **KV**。
3. **Create a namespace**：
   - 显示名称建议：**`OG_INDEX`**（仅便于人类识别；绑定 Worker 时用 **Namespace ID**，不是显示名）。
4. 创建后打开该 namespace → 复制 **Namespace ID**（UUID 形态）。

**暂不需要**在 Pages 项目里绑定 KV；绑定发生在 **34.4 独立 Worker 仓库** 的 `wrangler.toml`（`[[kv_namespaces]] binding = "OG_INDEX"`）。主仓只通过 **REST API bulk put** 写数据。

## 3. API Token 权限

可与 Pages 部署共用 **`CLOUDFLARE_API_TOKEN`**，也可单独建 Token（职责分离更稳妥）。

**最小权限建议**（Account 级）：

| 权限 | 级别 |
|------|------|
| **Account** → **Workers KV Storage** | **Edit** |

若 Token 仅用于 KV 同步、不部署 Pages，不必包含 Pages Edit。

**不要用** R2 的 S3 Access Key 写 KV；KV 走 Cloudflare API + Bearer Token。

## 4. GitHub Actions Secrets

路径：**仓库 Settings → Secrets and variables → Actions → Repository secrets**。

### 4.1 必填（启用 KV 同步）

| Secret | 说明 |
|--------|------|
| `CLOUDFLARE_ACCOUNT_ID` | 与 P18.6 Pages 相同 |
| `CLOUDFLARE_API_TOKEN` | 具备 KV Storage Edit |
| `OG_INDEX_KV_NAMESPACE_ID` | §2 复制的 Namespace ID |

**启用逻辑**：三个变量**全部非空**时，nightly/monthly 在 export 后自动同步；**缺任意一个**则打印 `skip` 并 **exit 0**（不阻断 R2 / Pages 部署），与 R2 五件套行为一致。

### 4.2 可选（一般不必在 GitHub 设）

| 变量 | 默认 | 用途 |
|------|------|------|
| `OG_INDEX_SYNC_SCOPE` | — | 仅影响**单独**跑 `sync_og_index_kv.py` CLI 时的默认 `--scope`；cron 内已写死 nightly=`daily`、monthly=`full` |
| `OG_INDEX_KV_BATCH_SIZE` | `1000` | bulk 每批键数（最大 `10000`） |

### 4.3 本地 `.env`（仓库根目录，勿提交）

可复制 `.env.example` 中 P34.3 段：

```env
CLOUDFLARE_ACCOUNT_ID=your_account_id
CLOUDFLARE_API_TOKEN=your_api_token
OG_INDEX_KV_NAMESPACE_ID=your_namespace_uuid
# OG_INDEX_SYNC_SCOPE=full
# OG_INDEX_KV_BATCH_SIZE=1000
```

## 5. 一次性：全量写入 `movie:*`（必做）

在 **任意一台**能读取 `frontend/public/data/galaxy_data.json` 与 `today.json` 的环境执行（本地或 CI 导出后的 artifact 目录均可）。

### 5.1 前置文件

- `frontend/public/data/galaxy_data.json` — 完整导出（体积大，勿在聊天里粘贴内容）
- `frontend/public/data/today.json` — nightly `pick_movie_today` 产物

若本地没有 galaxy 导出，可先跑 export 或从 Actions artifact 解压上述两文件到同一路径。

### 5.2 执行全量同步

**PowerShell（仓库根目录）**：

```powershell
$env:CLOUDFLARE_ACCOUNT_ID = "..."
$env:CLOUDFLARE_API_TOKEN = "..."
$env:OG_INDEX_KV_NAMESPACE_ID = "..."
python scripts/cron/sync_og_index_kv.py --scope full
```

**bash**：

```bash
export CLOUDFLARE_ACCOUNT_ID=...
export CLOUDFLARE_API_TOKEN=...
export OG_INDEX_KV_NAMESPACE_ID=...
python scripts/cron/sync_og_index_kv.py --scope full
```

### 5.3 预期日志

```text
[og_index_kv] scope=full data_version='2026.05.10.daily.30' movies_in_galaxy=59123 today_date='2026-05-08'
[og_index_kv] bulk put keys=59125 batches=60 batch_size=1000
[og_index_kv] batch 1/60 ok keys=1000
...
[og_index_kv] CLI done scope=full keys_written=59125
```

（`keys_written` = 电影条数 + 2；批次数随电影数变化。）

### 5.4 控制台抽查

Cloudflare → KV → **OG_INDEX** → 浏览键：

- 存在 `meta:G`、`today`
- 随机打开 `movie:301334`（或你 `today.json` 里的 `movie_id`），JSON 含 `title` / `poster_url`

**耗时与限额**：约 6 万键会分多批 PUT；若 API 限流，可暂时调小并发（脚本为顺序批处理），或稍后重跑 `--scope full`（幂等覆盖写）。

## 6. 日常：nightly / monthly 自动同步

无需单独加 workflow step；逻辑已挂在：

| 脚本 | 调用点 | scope |
|------|--------|-------|
| `scripts/cron/nightly_vote_refresh.py` | `write_today_json_after_galaxy_export` **之后** | `daily` |
| `scripts/cron/monthly_refit.py` | 同上 | `full` |

**推荐 CI 顺序**（与 R2 手册一致）：

```text
export galaxy → validate → today.json → [og_index KV] → upload R2 → build frontend → pages deploy
```

### 6.1 验证 nightly（workflow_dispatch）

1. 打开 Actions → **P18.4 Nightly vote refresh** → **Run workflow**。
2. 在 **Run nightly vote refresh** 步骤日志中搜索 `og_index_kv`：

**Secrets 已配置且成功**：

```text
[og_index_kv] scope=daily data_version='...' movies_in_galaxy=... today_date='...'
[og_index_kv] bulk put keys=2 batches=1 batch_size=1000
[og_index_kv] done keys_written=2
```

**Secrets 未配置**（可接受，但 Worker 不会更新当日索引）：

```text
[og_index_kv] skip: set CLOUDFLARE_ACCOUNT_ID, CLOUDFLARE_API_TOKEN, OG_INDEX_KV_NAMESPACE_ID
[P18.4 nightly] WARN og_index KV not synced (OG_INDEX_KV_NAMESPACE_ID unset)
```

3. **Upload galaxy gzip to R2** 日志应 **不再**出现 `og-today.png` / `og_today_url`。
4. Artifact 列表应 **不含** `frontend/public/data/og-today.png`。

### 6.2 验证 monthly

同上，搜索 `scope=full` 与 `keys_written` 接近电影总数 + 2。

## 8. 34.4 Worker 侧你需要准备什么

主仓 **34.3 不负责** Worker 部署，但 Operator 应提前对齐：

1. **同一 KV namespace ID** 写入 Worker 仓库 `wrangler.toml`：

   ```toml
   [[kv_namespaces]]
   binding = "OG_INDEX"
   id = "<OG_INDEX_KV_NAMESPACE_ID>"
   ```

2. Worker 读键逻辑与上表一致（`env.OG_INDEX.get("movie:123")` 等）。
3. 路由上线后，PNG URL 形如 `https://themoviecosmos.com/og/movie/{id}.png?v={G}-{M}`（`v` 算法见 Phase 34 计划 §内容身份；实现归 34.4）。

**34.5** 再在**同 zone** Worker 注入 `/movie/*`、`/today` 的 HTML meta。

## 10. 故障排查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| `skip: set CLOUDFLARE_...` | Secrets 未配或名为空 | 补全 §4.1 三项 |
| `KV bulk PUT HTTP 403` | Token 无 KV Edit | 换 Token 或加权限 |
| `KV bulk PUT HTTP 404` | Namespace ID 错误或账号不一致 | 核对 ID 与 Account |
| `missing galaxy_data.json` | 未 export 或路径错 | 先跑 export / 指对 `--public-data-dir` |
| `movies must be non-empty` | galaxy 损坏或空导出 | 跑 `validate_galaxy_json.py` |
| nightly 只写 2 键，分享仍错图 | Worker 未上线或从未 `full` sync | 跑 §5 `--scope full` |
| monthly 很慢 | 全量 ~6 万 PUT 正常 | 观察批日志；失败可重跑 `full` |
| 社交预览仍显示旧 `og-today.png` | 平台缓存 + 前端未切 Worker URL | 等 34.6；Facebook Debugger 重抓 |

## 11. 回滚（紧急恢复静态 OG 图）

若 Worker 未就绪且必须恢复 P23.5 行为：

1. 在 `nightly_vote_refresh.py` / `monthly_refit.py` 中**临时恢复**对 `render_og_today_after_galaxy_export` 的调用（或单独手动跑 `python scripts/cron/render_og_today.py`）。
2. 恢复 `upload_galaxy_r2.py` 对 `og-today.png` 的上传与 manifest 字段（需从 git 历史还原相关片段）。
3. 重新触发 nightly，确认 artifact 含 `og-today.png` 且 R2 manifest 含 `og_today_url`。

回滚后 KV 数据可保留（无害）；恢复 Worker 后再以 `full` 覆盖即可。

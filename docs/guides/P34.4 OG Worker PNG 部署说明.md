## 2. 你要做什么（逐步清单）

按顺序打勾。任一步失败先停，**不要**先绑生产路由。

### 步骤 0 — 确认 P34.3 KV（约 2 分钟）

[Cloudflare Dashboard](https://dash.cloudflare.com/) → **Workers & Pages** → **KV** → **OG_INDEX**：

| 键 | 期望 |
|----|------|
| `meta:G` | 非空字符串（如 `2026.05.10.daily.30`） |
| `today` | **历史 key，不可读取、写入或恢复。** |
| `movie:{id}` | 大量条目（缺则 `/og/movie/*.png` 全退品牌图） |

记下 **Namespace ID**（UUID）→ 只写入子仓 `.env` 的 `OG_INDEX_KV_NAMESPACE_ID`。`wrangler.toml` 的 `id` / `preview_id` 由 `npm run sync-wrangler` 或 `npm run deploy` **自动从 `.env` 写入**（Wrangler 本身不读 `.env`）。

### 步骤 1 — 子仓 `.env` 与 Wrangler 认证（必做）

**1.1 安装工具**

```powershell
npm install -g wrangler
```

**1.2 准备 `.env`（勿提交 git）**

在 `themoviecosmos-og-worker` 根目录：

| 方式 | 操作 |
|------|------|
| **推荐** | 从主仓 `chronicle_v3_3d_galaxy\.env` 复制同名四项到子仓 `.env` |
| 或 | `copy .env.example .env` 后手填 |

子仓 `.env` 字段（与 `.env.example` 一致）：

```env
CLOUDFLARE_ACCOUNT_ID=
CLOUDFLARE_API_TOKEN=
OG_INDEX_KV_NAMESPACE_ID=
# OG_INDEX_KV_API_TOKEN=   # 可选；空则 deploy 用 CLOUDFLARE_API_TOKEN
```

**1.3 验证 toml 将从 `.env` 同步（不必手改 `wrangler.toml`）**

```powershell
cd E:\projects\themoviecosmos-og-worker
npm run sync-wrangler
```

脚本会把 `.env` 里的 `OG_INDEX_KV_NAMESPACE_ID` 写入 `wrangler.toml` 的 `id` / `preview_id`。仓库里的占位符 `REPLACE_SYNCED_FROM_ENV` 仅作模板，**以你本机 `.env` 为准**。

**1.4 载入环境并验证（仅 `whoami` / 手动 wrangler 时需要）**

```powershell
cd E:\projects\themoviecosmos-og-worker
. .\scripts\use-env.ps1
wrangler whoami
```

| 现象 | 处理 |
|------|------|
| `whoami` 显示账号 | ✅ 继续步骤 3 |
| 报 `You are logged in with an API Token. Unset CLOUDFLARE_API_TOKEN...`（在执行 `wrangler login` 时） | **正常**：说明 Token 已生效，**不要** `login`，用 `use-env.ps1` 即可 |
| `whoami` 鉴权失败 | 检查 Token 权限含 **Workers Scripts Edit**；或改用手动 OAuth（见 §6） |

> **注意**：Wrangler **不会**自动读取 `.env`。`npm run deploy` 已包含 `use-env.ps1` + `sync-wrangler-from-env.ps1`。若单独跑 `wrangler` 命令，需先 `. .\scripts\use-env.ps1`。

### 步骤 5 — 生产冒烟（历史 Today 项不可执行）

> **历史 Today 命令：不可执行。** 下方 `/og/today.png` 检查只记录旧状态；当前验证应以电影 PNG、品牌 PNG 和 `/today` 404 为准。

```powershell
curl -sI "https://themoviecosmos.com/og/brand.png?v=og-brand-og-v1"
# 历史 Today 命令：不可执行；当前 Today 路由必须返回 404。
curl -sI "https://themoviecosmos.com/og/today.png"
curl -sI "https://themoviecosmos.com/og/movie/301334.png"
```

将 `301334` 换成你 KV / `today.json`（历史 Today 文件，不可执行）中存在的 `movie_id`。

**通过标准**：

- 最终 **200**，`content-type: image/png`
- 带 canonical `v` 的 URL 上 `cache-control` 含 `immutable`
- `/og/today.png` 无 `v` 时常见 **302** → `Location` 带 `?v={G}-{M}`（历史 Today 行为，不可执行）
- 浏览器打开为 PNG：海报 + 片名（today 含 `today's pick · 日期`；历史 Today 内容，不可执行）

| 症状 | 排查 |
|------|------|
| 404 | 步骤 4 路由未绑或顺序不对 |
| 500 | Dashboard → Worker → Logs |
| 始终是品牌图 | 步骤 0：缺 `movie:{id}` 或 id 不在 KV |

## 6. 常见问题

### `npm run deploy` 报 `Authentication error [code: 10000]`

`dry-run` 能通过但 **deploy 失败**，几乎都是 **API Token 权限不够**（不是 KV id 配错）。

| 检查 | 操作 |
|------|------|
| Token 类型 | 主仓 P18.6 / P34.3 常用 Token 只有 **Pages Edit** + **KV Edit**，**不能**部署 Worker |
| 所需权限 | Cloudflare Dashboard → **My Profile** → **API Tokens** → 编辑或新建 **Custom Token**，Account 级至少：**Workers Scripts → Edit**（另建议保留 **Workers KV Storage → Edit**） |
| 验证 | 更新 `.env` 的 `CLOUDFLARE_API_TOKEN` 后：`npm run sync-wrangler` → `. .\scripts\use-env.ps1` → `wrangler whoami`（应显示邮箱/账号，而非再次 10000） |
| account_id | `npm run sync-wrangler` 会把 `.env` 的 `CLOUDFLARE_ACCOUNT_ID` 写入 `wrangler.toml` 的 `account_id`（与错误提示一致） |

**OAuth 替代**：若不想改 Token，可 `Remove-Item Env:CLOUDFLARE_API_TOKEN` 后 `wrangler login`，再 `npx wrangler deploy`（不用 `deploy.ps1`，以免再次注入旧 Token）。

---

**Q：`wrangler login` 报 API Token 已设置？**  
A: 主仓或当前终端已有 `CLOUDFLARE_API_TOKEN`。在子仓执行 `.\scripts\use-env.ps1` + `wrangler whoami`，**无需** `login`。

**Q：每次开新终端都要 `use-env.ps1` 吗？**  
A: 是。仅对当前 PowerShell 会话注入 `$env:CLOUDFLARE_*`。

**Q：`.env` 和 `wrangler.toml` / `.dev.vars` 什么关系？**  
A: **`.env` 是唯一 SSOT**（账号 Token + KV Namespace ID）。`wrangler.toml` 里的 KV `id` 由 `npm run sync-wrangler` 从 `.env` 生成；Wrangler **不会**自动读 `.env`。`CLOUDFLARE_*` 由 `use-env.ps1` 注入进程（`npm run deploy` 已包含）。可选 `.dev.vars` 仅用于你愿意维护第二份文件时；本仓不强制。

**Q：能否只改 `wrangler.toml` 不改 `.env`？**  
A: 不推荐。下次 `npm run deploy` 会用 `.env` 覆盖 toml。请只维护 `.env`。

**Q：主仓 PR 合并会更新 Worker 吗？**  
A: **不会**。KV 由主仓 CI（P34.3）更新；Worker 代码要在子仓 `git pull` 后再 `use-env.ps1` → `npm run deploy`。

**Q：只 deploy、不绑路由？**  
A: 公网 `/og/*` 仍走 Pages，预览不变。步骤 4 必做。

**Q：Namespace ID 要进 GitHub 吗？**  
A: `wrangler.toml` 含 UUID 时提交到 Public 仓库风险较低，但仍建议只放在 `.env` + 本机 toml；团队各自 `.env` 对齐即可。

**Q：无 Token 时如何 OAuth 登录？**  
A:

```powershell
Remove-Item Env:CLOUDFLARE_API_TOKEN -ErrorAction SilentlyContinue
wrangler login
```

勿在同一终端同时 `use-env.ps1`（会再次注入 Token）。

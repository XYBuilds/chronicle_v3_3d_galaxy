Problem

搜索回显 module 决定 select 生命周期；`clearSearch()` 当前清掉规范要求保留的 `selectionIds`。

Solution

把进入 focus、切换 focus、退出 focus、保留或退出 select 的状态转移集中到一个 deep module。

locality：状态规则集中 leverage：四个入口复用 测试命中完整序列 修复规范漂移
约束：保留 `selectionPhase` 为 `scene.ts` 的时间驱动 implementation；不要把它迁入 Zustand。

Deletion test：删除该 module 后，focus/select 优先级、清理时机、邻域 mask 与 ESC 恢复规则会重新散落到 SearchBar、App、interaction、scene 与 store 调用方。

Problem

`visualConfig.ts` 声称权威，但只覆盖 exporter；runtime 仍直接拆解 defaults、profile、debug state 与 uniforms。

Solution

让同一 module 拥有配置解析、renderer 应用、provenance 与 diagnostics，runtime/export 只保留 adapter。

locality：视觉概念集中 leverage：两端同实现 测试一个 render seam 减少 uniform 泄漏
约束：保持 C-003 的 `visual_config_hash`、metadata 与 PNG 结果；不要把 runtime diagnostic override 混入生产 hash。

Deletion test：删除 `visualConfig.ts` 会迫使 main、diagnostics 与 metadata 调用方重新组合 defaults、validation、provenance 和 hash；继续加深能阻止 uniform application 再次扩散。

Problem

Solution

locality：运行准备集中 leverage：两条任务复用 策略测试更窄 调用顺序少泄漏
约束：Data Pipeline SSOT 要求 nightly 冻结 threshold、monthly 重算 threshold；不能用一个宽条件分支抹平差异。

Deletion test：删除公共执行 module 后，两份下载 fallback、环境准备、export 和 validator 编排会再次出现；两个实际 adapter 已证明 seam 真实存在。

Problem

Solution

让一次 profile-safe release 的状态与结果成为 deep module；workflow 仅提供 nightly/monthly 策略。

locality：失败状态集中 leverage：双模式复用 测试稳定 release outcome 减少顺序断言
约束：C-004 的 immutable assets 与 pointer-last 是硬约束；C-002 的 OG sync 必须继续位于 R2 release 之前。

Deletion test：删除 transaction 后，pointer 校验、manifest 准备、失败回退与 final commit 规则会重新泄漏到 workflow、policy module 和上传调用方。

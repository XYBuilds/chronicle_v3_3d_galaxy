# **电影宇宙「每日星轨观测」系统 PRD (Product Requirements Document)**

## **1\. 产品概述 (Product Overview)**

### **1.1 背景与痛点**

目前已完成核心资产：“基于 TMDB 与 UMAP 算法的 3D 电影宇宙”项目。该项目以中立、客观的视角收录了人类电影史上的全量样本。作为静态的数据库，它缺乏将这种“数字档案”与真实世界连接的纽带以吸引具有探索欲的用户。

### **1.2 产品目标**

打造一个“数字文化天文台”。以每日热点事件为引，挖掘现实事件与特定电影之间绝妙的讽刺、反差或隐喻联系。

**核心理念：** 推荐并非为了“催促观看”，而是展示“现实世界与数字宇宙的结构性共振”，以此满足好奇心并实现引流。

## **2\. 系统架构与技术栈 (Architecture & Tech Stack)**

* **大模型编剧室 (Multi-Agent 架构)**: 采用物理隔离的智能体工作流。不同 Agent 拥有独立且详尽的“哲学/人格准则”文档，异步并发执行新闻的意图拆解。  
* **信息源**: **RSS 订阅源** (通过 Python feedparser 直接抓取)。  
* **总编与决策台 (Human-in-the-Loop)**: 创作者（人类）作为总编，**Obsidian** 作为“每日星轨简报”的呈现终端，由人来完成最终的火花甄别。  
* **核心检索基建 (专项优化)**: **构建全新的“纯文本搜索专用库 (Search-only Index)”**。剔除原有 UMAP 模型中对 Genres (流派) 和 Original Language (语言) 的向量拼接。仅使用 paraphrase-multilingual-MiniLM-L12-v2 对文本（Tagline \+ Overview）进行 L2 归一化编码。**以此打破类型壁垒，实现纯粹基于剧情结构和隐喻的跨界检索。**

## **3\. 核心处理逻辑：多维抛饵与人工甄别 (Processing Design)**

### **阶段一：全景抛饵 (Panoramic Retrieval)**

1. **现实波澜 (Fact Input)**: 抓取当日核心新闻事件。  
2. **多智能体并发裂变 (Agent-based Query Fission)**:  
   新闻被同时发送给 7 个物理隔离的专属 Agent。每个 Agent 遵循严格的【去实体化 (De-entification)】约束，结合自身详尽的行为哲学，输出一句“伪剧情简介”。  
   * **A1 现实记录员**: 直译核心物理动作。  
   * **A2 社会学家**: 寻找阶级撕裂与资源矛盾。  
   * **A3 心理医生**: 坍缩为个人心理创伤或偏执。  
   * **A4 神话学者**: 套用古典悲剧/史诗内核。  
   * **A5 边缘视界导演**: 聚焦边缘小人物视角的荒诞日常。  
   * **A6 视觉美学师**: 提炼纯粹的视听奇观与感官氛围。  
   * **A7 混沌理论家**: 倒推极其微小/荒谬的灾难起因。  
3. **跨类型纯文本召回 (Text-only Vector Search)**:  
   Python 将这 7 段生成的文本输入给“纯文本搜索专用库”，在完全不考虑流派和语言的情况下，通过 KNN (如 FAISS 或 Numpy 余弦相似度) 各自检索距离最近的 Top 2。获得 **\~14 部候选电影**。

### **阶段二：人工鉴赏与输出 (Human Curation)**

4. **生成每日简报 (Daily Dossier)**:  
   系统自动将这 \~14 部电影以 Markdown 格式写入 Obsidian。格式包括：【原新闻】 \-\> 【触发该候选的 Agent 视角及其生成的伪剧情】 \-\> 【匹配到的真实电影 Title, Overview, Genres, 匹配度】。  
5. **人类总编拍板 (The Chief Editor)**:  
   创作者在 Obsidian 中阅读简报，凭借人类独有的幽默感和哲学顿悟，选出最具“绝妙讽刺/宿命隐喻”的那一部电影。  
6. **视觉切片与定稿**:  
   创作者提取目标 movie\_id，手动在命令行调用 generate\_planet.py \--movie\_id=XXX 生成星球视觉图。配上两句冷峻的观测短评，发布至社媒。

## **4\. 系统自动化工作流 (Workflow)**

整个自动化管线仅运行至 Obsidian 归档步骤：

* **Step 1 \[脚本调度\]**: 每日定时拉取 RSS，获取 1 条最具张力的新闻。  
* **Step 2 \[大模型并发\]**: Asyncio 调用 7 个 Agent 接口，获取 7 段去实体化的伪剧情文本。  
* **Step 3 \[向量检索\]**: 将 7 段文本转化为 7 个 Vector，与本地的“纯文本 Search-only Index”比对，召回 14 组结果。  
* **Step 4 \[组装写入\]**: 渲染 Markdown 模板，写入 Obsidian 目录（如 Daily\_Briefing/2026-05-28.md）。  
* **(结束自动化)** \-\> 等待人类总编开启新的一天，进行审阅。

## **5\. 网页端承接能力 (现有基础)**

前端已支持通过 URL ?focus\_movie=xxx 自动实现深层链接跳转、相机飞跃动画及详细信息面板的展开。

## **6\. 实施计划 (Roadmap \- Phase 1\)**

**Cursor 建造期首要任务序列：**

1. **\[算法层 \- 基建\]**: 基于现有的电影库数据，重跑一遍 paraphrase-multilingual-MiniLM-L12-v2，**生成一份去除 Genres 和 Language、纯保留文本特征的 Numpy .npy 或 FAISS 索引文件，专用于本系统的检索**。  
2. **\[逻辑层\]**: 编写 Python 脚本集成 feedparser。  
3. **\[大模型层\]**: 建立 prompts/ 文件夹，编写 7 个隔离的 Agent Persona 配置文件。  
4. **\[集成层\]**: 编写主控脚本 main.py，实现：拉取新闻 \-\> 并发请求 LLM \-\> 提取返回文本 \-\> 向量库检索 \-\> 生成 Obsidian Markdown 文件。

# Clarify GitHub suspension boundaries and account-content recovery

## Question

What do current first-party GitHub terms, acceptable-use policies, support procedures, and account-content provisions establish about: appealing an unexplained suspension; using an already-existing second account while the main account is suspended; requesting repository and account content; applicable deadlines; and actions that could expose the second account to enforcement? Separate explicit policy from inference, and produce a safe interim operating boundary rather than guessing why the account was suspended.

## Resolution comments

### 2026-08-17 — Resolved

[Research evidence](../../../research/github-suspension-account-boundaries.md) — Treat the suspension as an unexplained account-control-plane outage. Keep the existing secondary GitHub account out of repository hosting, Actions, secrets, transfers, and support discussion until GitHub gives written guidance. Continue the official appeal in one existing case, request immediate preservation/export of lawful account content, and ask GitHub to identify whether the action is a suspension, termination, or other restriction. GitHub publishes a six-month appeal boundary, while the Terms' 90-day content-copy request expressly covers cancellation, termination, or downgrade rather than a mere suspension; the protective request should therefore be made now.
